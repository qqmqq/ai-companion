# 让角色有时间概念：现实时间基准 + 记忆时间戳

日期：2026-09-19 ・ 目标：角色不该活在一个「永远现在」的世界里 —— 它要能说「好久没聊了」「都这个点了」，
也要知道「你说过的事」是三天前还是三个月前说的。

> 后续：实测反馈「隔了几个小时，角色还在接着上一轮的话题讲」—— 光有时间基准不够，还得给动作规则。
> 间隔分类、紧贴当前消息的间隔提醒、以及可编辑的对话提示词，见 `docs/PROMPT-AND-TIME-GAP-REPORT.md`。

## 1. 之前的问题（不是没时间戳，是没把时间给模型）

数据库里一直有时间：消息有 `createdAt`，记忆有 `occurredAt` / `createdAt`，事件有 `dueAt`。
但装配上下文时**一个都没带上**：

- 记忆注入长这样：`- 用户喜欢手冲咖啡` —— 不管这条是昨天记的还是半年前记的，模型读起来一样新鲜；
- 没有任何「现在几点」的基准，模型只能靠猜；
- 事件那一段更糟：`when.slice(0, 16).replace("T", " ")` —— 直接切 ISO 字符串，
  等于把 **UTC 当本地时间念**（东八区差 8 小时），「9月20日 12:00 的约」会被念成「04:00」。

## 2. 做了什么

### 2.1 一个纯格式化模块（可被用例钉死）

`backend/src/util/time-format.ts`：

| 函数 | 输出 | 用途 |
| --- | --- | --- |
| `describeNowForPrompt` | `2026年9月19日 周六 14:32（下午）` | 「现在是…」 |
| `formatDateTimeLocal` | `2026-09-16 20:14` | 具体时刻 |
| `formatShortMoment` | `9月16日 20:14` | 说「什么时候」时省掉年份 |
| `describeRelative` | `刚刚 / 12 分钟前 / 3 小时前 / 昨天 / 3 天前 / 1 周前 / 1 个月前 / 1 年前` | 「多久以前」 |
| `describeDayPart` | `凌晨 / 早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 深夜` | 口气 |

只在整数量级上说人话（「3 天前」而不是「3.214 天前」）；解析不了的输入原样返回，绝不抛错。
时区默认取系统本地时区，可用设置项 `context.timeZone` 固定（用例都固定成 `Asia/Shanghai`，因此 CI 在 UTC 也稳定）。

### 2.2 上下文新增「现实时间」这一区（`time_context`）

排在应用约束之后、人设之前，优先级与角色定义同档（**永不因预算被丢**，它只有几十个 token）：

```
现在是 2026年9月19日 周六 14:32（下午）（本地时间）。
你们上一次说话是 2026-09-16 20:14（3 天前）。
距离用户上一次开口：3 天前。
距离你上一次说话：3 天前。

说话时可以自然带出时间感（例如「好久没聊了」「都这个点了」），但注意：
- 间隔很久就当作隔了很久，刚聊完就接着上文，别说反；
- 不要念出具体日期数字，也不要说「系统时间」「时间戳」这类机制词。
```

第一次说话时不说「上次」：直接写「这是你们第一次说话，之前没有聊过」。
（历史只查一次，时间基准与「最近对话」两段共用同一份，口径不会打架。）

### 2.3 记忆带上现实时间戳

```
以下是与当前话题相关的长期记忆（方括号里是它发生的时间与距今多久）：
- [2026-09-16 20:14・3 天前] 用户喜欢手冲咖啡
提到这些事时请把时间说对：很久以前的事别当成刚刚发生。
```

### 2.4 顺手修掉的时区 bug

事件段的时间改用 `formatShortMoment`（本地时间 + 距今多久）：
`- 去机场接你朋友（9月20日 12:00・明天）`，不再是 UTC 切片。

### 2.5 界面上也看得见

「记忆」页每条记忆多一行「**记于 2026-09-16 20:14（3 天前）**」（检索结果里也有）——
角色看到的和用户看到的是同一个时间口径。前端 `frontend/src/lib/moment-text.ts` 与后端同一套说法（前端不能 import 后端源码，所以是独立实现）。

## 3. 纪律

- 只给事实与措辞边界，**不替角色写台词**（与人设、情绪、关系几段同一套做法）；
- 时间戳只在上下文里，不改变任何接口返回结构；
- 结构化日志与快照里不新增任何敏感信息（快照照旧只存分区与来源 id）。
