# 事件与任务：按角色区分（谁的事）

日期：2026-09-17 ・ 需求：「目前的事件与任务不分角色，添加识别是哪个角色接收的任务区分开」

## 1. 后端本来就有"归属"，缺的是界面

事件、任务、定时提醒三种记录**都带 `characterId`**（`/api/events`、`/api/tasks` 还支持 `?characterId=` 过滤），
只是「事件与任务」页把它们揉在一起平铺，看不出哪条是谁的事。

## 2. 改了什么（`frontend/src/pages/timeline.tsx` 重写）

| 改动 | 说明 |
| --- | --- |
| **按角色分组** | 一个角色一个小标题「Aria（3）」，各自一组卡片；通用/已删除角色单独成组 |
| **每条标出归属** | 卡片上写「属于：Aria」（查不到角色名时写「已删除的角色」，绝不放一串 id） |
| **按角色筛选** | 顶部「看谁的事」下拉：全部角色（事件 N・任务 M・提醒 K）／每个角色（带他的总数）／通用 |
| **筛选联动新建** | 筛到某个角色后，新建事件默认记在他名下；表单标签改成「这个事件是谁的事」 |
| **提醒也带角色** | 定时提醒卡片同样显示「属于：X」并参与分组/筛选 |
| **空状态说实话** | 筛到某人而他什么都没有时显示「「Kai」还没有事件」，而不是笼统的"还没有事件" |

## 3. 归属是怎么定的（这条链路值得记下来）

- 事件：创建时指定（表单里选的角色，默认第一个）；
- 任务：来自事件时继承事件的角色；
- **定时提醒：由"当时在聊的会话属于哪个角色"决定** —— 所以你在微信里换到「Nova」之后说的提醒，会记在 Nova 名下（见下面的测试）。

## 4. 验证

### 前端（jsdom 真渲染）

`frontend/test/timeline-characters.test.mjs`（3 用例）：

1. 三段都按角色分组（Aria（1）／Kai（1）／**已删除的角色（1）**），每条卡都写着「属于：X」，界面上不出现角色 id；
2. 筛到Kai：Aria的条目（事件+提醒）全部消失、分组标题里也没有Aria、三段计数都变成 1，且新建事件的默认角色跟着变成Kai；
3. 筛到「通用」：空状态说清是这一组没有东西。

### 后端（归属不能错）

`backend/test/integration/scheduled-message.test.ts` 新增用例：微信侧先跟第一个角色聊 → 发「切换角色 Kai」→ 再说「1分钟后给我发消息」→ **断言这条提醒的 `characterId` 是Kai**（不是第一个角色），message 原文也对得上。

### 真机（运行中的后端真实数据）

```
角色：Aria / Nova
定时提醒 2 条 → 角色 Aria
页面分组标题：Aria（2）
筛选框：看谁的事 全部角色（事件 0・任务 0・提醒 2）
页面报错：无
```

（事件与任务当前都是 0 条，是你之前清理掉的；Nova 暂时还没有属于他的事件/提醒。）
