# 对话提示词补充（可编辑）+ 间隔割裂的修复

日期：2026-09-19 ・ 起因：用户反馈「隔了几个小时，角色还在接着上一轮的话题讲，很割裂」，并要求能自己改提示词。

## 1. 割裂是怎么来的

上一轮刚加了「现实时间」那一段（`time_context`），模型确实知道「上一次说话是 6 小时前」，但：

- 那段话在最前面（应用约束之后），而当前消息在**最后**；模型读到要回话时，中间隔着几十条历史消息，
  历史读起来是**连续**的一段对话 —— 于是它顺着上文往下接；
- 那段里的措辞也太软（「间隔很久就当作隔了很久」），没有可执行的动作。

## 2. 现在怎么处理

### 2.1 间隔分类（可执行，不是形容词）

`backend/src/util/time-format.ts` 新增 `describeGapKind()`：

| 间隔 | 说法 | 是否「重新开口」 |
| --- | --- | --- |
| < 5 分钟 | 接着刚才的话题 | 否 |
| < 1 小时 | 过了一会儿 | 否 |
| < 2 小时 | 隔了一两个小时 | 是 |
| < 12 小时 | 隔了几个小时 | 是 |
| < 30 小时 | 隔了大半天 | 是 |
| 更久 | 隔了一天以上 | 是 |

### 2.2 「现实时间」那一段给出明确动作

```
怎么处理这次间隔（务必遵守）：
- 这次是「隔了很久之后重新开口」（隔了几个小时）：
  先用一句符合你性格的招呼、或对间隔本身的反应开头（比如问对方忙完没、这个点在做什么），
  **不要**接着几个小时前的话题往下讲，也不要问「刚才说到哪了」—— 对方会觉得你没在听现在的他。
  对方自己又提起旧话题时，再接着那个话题聊。
- 不要念出具体日期数字，也不要说「系统时间」「时间戳」这类机制词。
```

间隔很短时对应的说法是「这次是『接着刚才聊』：正常顺着上文说，别说『好久不见』『你都好久没理我了』这类话」。

### 2.3 在新消息之前再钉一句（新分区 `time_gap`）

只有间隔 ≥ 2 小时才出现，位置在**最近对话之后、当前消息之前**（呈现顺序 12，紧贴当前消息）：

```
（提醒：上一句对话是 2026-09-19 14:20 说的，也就是6 小时前 —— 隔了几个小时。）
请把这次当成「隔了很久之后重新开口」：先回应对方此刻说的话，不要接着上次的话题往下讲；对方又提起旧话题时再接着聊。
```

优先级与「最近对话」同档（3）—— 它只有几十个 token，却决定这次回复是不是割裂，绝不因预算被丢。

## 3. 对话提示词补充（用户可编辑）

- 设置项 `prompt.custom`（最长 4000 字），界面在「模型设置 → **对话提示词（可选）**」：一个输入框 + 「保存提示词」「清空」，
  保存后提示「已保存，下一句起生效」；
- 注入位置：**系统约束**那一段的末尾，标题写明「用户自定义要求（由使用者本人填写，优先遵守；但不得违反上面的约束）」——
  也就是说它能调语气、称呼、禁忌，但改不掉「不要替用户说话」「不要编造事实」这类底线；
- 只对**所有角色**生效；单个角色的设定仍然在角色卡（角色工坊 / 编辑角色）里改；
- 接口：`GET /api/context/prompt`、`PUT /api/context/prompt`；超长在入口就被拦（400）。
